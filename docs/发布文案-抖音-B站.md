## 口播稿（连读版，约 45 秒）

> 为什么你的 AI 陪聊一眼就能看出是机器？
>
> 第一个坑，记忆按会话存。你在私聊告诉它"我叫老王"，切到群里问它我叫什么，它会说"抱歉我不知道"。换个地方就不认识你了。
>
> 第二个坑，回复唰一下全出来。你看真人怎么打字——正在输入、停一下、发一句、再停一下。它是一秒钟吐一大段。

> 第三个坑，什么时候都说话。群里别人闲聊它也要插一句，五分钟就被踢出去了。

>
> 记忆按人存、打字有节奏、该闭嘴的时候闭嘴。每一层都能单独拿出来用。
>
> 代码开源了，链接在评论区。

## 视频结构（8 分钟）

### 00:00–00:35 · 开场钩子

**画面**：直接放对比 —— 左边 AI 秒回客服腔，右边真人节奏分条发

**口播**：
> 先看两段对话。
> 左边这个，你问它"在吗"，零点二秒之后回你"在的！有什么可以帮您的吗？我随时都在哦～"
> 右边这个，一点二秒回一个"在"，三点四秒"咋了"，七点一秒"说事"。
>
> 左边是大多数 AI 陪聊，右边是我想要的。
>
> 这个视频讲的就是：**为什么差这么多，以及我是怎么做的**。代码已经开源了。

**屏幕字**：`0.2秒 vs 7.1秒`  `同一个模型`

---

### 00:35–02:10 · 三个坑（核心内容）

**画面**：`02-三个问题.png` 这张图，逐块放大

**口播**：
> 做这个之前我先复盘了市面上 AI 陪聊的通病。跟模型强弱没关系，栽在三个地方。
>
> **第一个，记忆按会话存。**
> 大部分实现是"一个会话一个记忆桶"——私聊一个、群 A 一个、群 B 一个。结果就是同一个人换了个地方，AI 就失忆了。
> 我改成按**人**存。用账号 ID 当 key，不管他在哪说话，读写的都是同一本账。
>
> **第二个，回复唰一下全出来。**
> 大模型是流式的，但你如果一次性发出去，就是零点几秒吐一大段。真人不是这样的——会先"正在输入"，然后一句一句发，中间还停顿。
> 我写了个 Humanizer，打字时长按字数算、加抖动、深夜自动变慢，长回复自动切条，条间随机停 700 到 2600 毫秒，还有 25% 概率停久一点（像被什么事打断了）。
>
> **第三个，什么时候都说话。**
> 群聊里别人闲聊它也要插嘴，很快就被踢了。
> 我把它拆成六个独立条件：被 @、被叫名字、被提问、被拍一拍、出现关键词、随机概率。任何一个命中才醒，否则一个字不说。

---

### 02:10–03:40 · 演示一：记忆

**画面**：终端录屏，跑 demo

**口播**：
> 直接看效果。我写了段离线 demo，不需要 API key 就能跑。

```bash
node examples/demo.js
```

> 这里模拟一个人先在私聊说话、后来又在群里说话。

**屏幕字**：`data/people.json` · `data/turns.jsonl`

### 03:40–04:50 · 演示二：打字节奏

**画面**：demo 输出的时间轴

**口播**：
> 这是拟人化发送的实际时间轴。

```
+     0ms  正在输入…
+  2357ms  发出：刚看到消息。你那事我想了一下，感觉不用太急
+ 12072ms  正在输入…
+ 13463ms  发出：明天先问问再说吧
+ 24490ms  正在输入…
+ 25770ms  发出：我先去吃饭了
```

> 三段话，二十五秒发完。中间还夹了一次九秒多的"长停顿"。
>
> 这个长停顿是故意的——真人在打字的时候会走神、会去看一眼别的窗口、会突然想起来要说什么。
> 加上这个之后，"像人"的感觉会明显很多。

**屏幕字（弹幕点）**：`👆 这就是"人味"`

### 04:50–06:10 · 演示三：手机控制

**画面**：手机录屏 + 代码

**口播**：
> 第二部分是另一个独立项目，叫 phone-mcp。
>
> 它通过 adb 把安卓的操作能力包装成 34 个 MCP 工具。**手机侧不需要装任何东西**，只要开着无线调试或者插着 USB。
>
> 能干什么？点按、滑动、输入中文、截图、看界面结构、录屏抽帧、开 App。
>
> 最有用的是这个，`phone_macro`——一次调用执行一整串操作。

```json
{
  "actions": [
    { "type": "tap",   "x": 1120, "y": 530 },
    { "type": "swipe", "x1": 640, "y1": 600, "x2": 640, "y2": 200 },
    { "type": "text",  "text": "你好呀" }
  ],
  "repeat": 10,
  "saveAs": "daily_run"
}
```

> 还可以存成命名宏，下次一行就能重放。玩游戏、刷视频、重复签到，比一次次点快几十倍。
>
> 另外还接了网易云音乐和 QQ 空间——不过那部分有风险，评论发出去撤不回，所以我加了限流：每十分钟一条，每天三条。

### 06:10–07:20 · 架构 & 设计原则

**画面**：`03-架构.png`

**口播**：
> 整个架构四层：**收发 → 该不该醒 → 生成回复 → 怎么发**。
>
> 每一层都能单独用。你只想要"像人打字"，`new Humanizer()` 就完事，不用管其它三样。
>
> 我做的时候守了几条：
> 一，不绑定平台。QQ 只是一个 transport 实现，换微信、Telegram 只要照接口再写一个。
> 二，不绑定模型。只要那个接口是 OpenAI 格式，DeepSeek、Kimi、本地 Ollama 都行。
> 三，数据都是纯文本。
> 四，不确定的事明确报错，不静默失败——比如没装中文输入法就直接告诉你没装，而不是默默把字丢掉。
>
> 最后一条我觉得最重要：**该闭嘴的时候闭嘴**。一个不会看场合的机器人，比不会说话的更烦人。

**屏幕字**：`不绑定平台` `不绑定模型` `纯文本数据`
